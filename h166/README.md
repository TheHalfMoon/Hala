# H166 — one-step visual merger gradient and memory qualification

**Research gate only — NOT a new Hala model, NOT a new native benchmark.**

## Baseline and why this probe exists

H164's independent new-application browser evaluation found 1/64 real task
success for frozen H161, versus 10/64 for H164 on two held-out original
apps (Pell 0/32→7/32, Pikaday 1/32→3/32). However 54/64 H164 predictions
still failed real native app tasks; Arabic was 0/32→1/32. Those 64 scenes
were one-shot consumed and **must never be evaluated, trained on, reselected
or tuned against again**. Previous H140/H162/H163 holdouts are also locked.
The improvement is exploratory, not broad computer-use reliability.

The H164 control used only language-layer LoRA and deliberately did not train
the visual backbone. A small projection-only adapter is a research hypothesis:
it might improve image-to-language spatial information but must first fit
on the **free Nvidia T4** with explicit memory evidence. No paid fallback.

## One-step synthetic-only T4 gate

- Frozen external research base:
  `patrickballou/gui-assist-grounder` revision
  `31632edaa20749c7f532868a42635f7240033106`.
  Verify actual downloaded architecture; never invent module names.
- Inspect `named_modules()` and permit **only nn.Linear modules nested
  within `visual.merger`**, at most four. Fail closed if no match, a language
  layer is selected, or any non-LoRA parameter is trainable.
- Use rank-4 LoRA, alpha 8, no dropout, frozen base. Execute precisely
  **one optimizer step** on a deterministic **synthetic 960×720 white canvas
  with a single red square**, not a screenshot from any user application.
  The label is known because the canvas was generated by this code.
- Require matching GPU environment (pinned torch/transformers/peft/Pillow),
  actual T4, finite supervised loss, at least one nonzero finite gradient,
  changed trainable visual adapter parameters, and optimizer state.
  Reject peak allocated GPU memory above **13.0 GiB**; no attempt to
  claim 16 GiB headroom or move to a paid card.
- Only report CUDA memory and gradient counts, selected module names, pinned
  base SHA, and non-sensitive environment versions. **Never save model
  weights**. Private Kaggle code job has **zero datasets attached**.
- A failure or OOM is a research NO-GO; do not silently retry on another
  accelerator or reduce the holdout standard.

## Next distinct work after any successful probe

A synthetic gradient is **NOT evidence of real visual grounding gains**.
Before any visual+language SFT, freeze a **new TRAIN-only** multi-application
source with independent replay, donor license checks, near-duplicate controls,
bilingual and multi-layout coverage and a new separate DEV split.
Use the H164 adapter only as an immutable baseline, with explicit
compatibility tests before stacking trainable adapters. Then preregister
completely fresh unrelated OOD app families and native click/drag/type
scoring, requiring per-app and Arabic improvements (not just valid JSON).
No evaluation on consumed Pell/Pikaday OOD or past sealed sets.

**No public model/media, Hala 35B changes, paid compute, main merge or release.
Keep H166 Draft.**
