# H264 — screenshot-locked offline native action bridge

**RESEARCH-ONLY. Not a trained Hala model, new independent test, official
TRAIN/DEV/OOD admission, or evidence of neural improvement.**

H263 made screenshot-coordinate native browser input real. H264 closes a
specific failure path: a policy can take time to generate an action while
the underlying page changes. Without explicit pre-action re-observation,
an otherwise well-formed old click could apply to the wrong visible state.

## Narrow, fail-closed research implementation

The only accepted application for this stage is the **H262 original
Hala-authored first-party Stockroom** source at the exact byte hash
`3ece76b7f884c96de53a5a4f30d1d24984f01f13b059d4e495ccadd7eb08848a`.
The path must resolve to an unchanged `h262/stockroom.html`; no
untrusted external website, copy of an altered HTML file, or third-party
asset is allowed. H262 is an invented functional app, NOT independent OOD.

`run_local_research_episode` creates a **fresh** offline Playwright context
with fixed 960x720 viewport, network emulation offline, disabled downloads,
no permissions and disabled service workers, plus a deny route for external
HTTP(S)/WS(S) subresources. A route guard alone is not proof of a
system-wide network sandbox. Only explicitly authorized owner-local
first-party research is in scope.

For each of at most eight steps:
1. Verify the original local file SHA and exact browser URL/viewport.
2. Capture one **decoded real 960x720 screenshot PNG**, in memory only.
3. Supply only that PNG and H199's screenshot-only task prompt to the
   injected callable. The callable never receives DOM, selector, source,
   gold, hidden state, page object or private reference geometry.
4. Validate the **exact single-action H199 JSON**, rejecting malformed,
   duplicate-key or extra-action output without sending input.
5. Verify the original page URL, original file SHA and viewport again.
6. Capture a fresh screenshot and require byte-identical PNG SHA256 digest
   to the exact model-visible image, before dispatching any native action.
   A stale image **fails closed** without a click, drag, type or scroll.
7. Execute the one native action using H263's real mouse/keyboard bridge
   and recheck the pinned page immediately after. An `abstain` stops the
   loop without any browser actuation.

A screenshot hash comparison is an observational guard **not** an atomic
transaction. It cannot prove that no mutation occurs between the second
screenshot and dispatch. This is bounded local research, not a production
computer-use safety guarantee.
