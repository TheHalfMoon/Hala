# Hala engineering rules

Read CLAUDE.md when present. Keep Hala independent of Aladdin; never modify the Aladdin repository. Model output is untrusted advice, never authority or a completion receipt. No paid compute, third-party telemetry, customer-data training, or multi-GB local model downloads. Preserve existing work and shared history. English only; Arabic text is permitted as evaluation data.

Every meaningful change requires genuine tests, Jev semantic evidence, PStack independent review, and supported Graft qualification. Unavailable gates remain incomplete. Never equate mocks, vendor scores, or proposed experiments with measured model qualification. Merge and deployment require founder authorization.

## Source-backed EGM design reviews

For new architectural or model-learning strategy work, read `docs/egm/HALA.md` and the living proposed design `docs/designs/hala-rtl-visual-action-learning-egm.md`. The upstream Google EGM plugin is an optional **review workflow**, not a model or a replacement for Jev/PStack/Graft gates. A real Goldfish review needs a verified fresh-context read-only subagent, the pinned EGM personas and standards, actual source reads, and an independently completed report. If these are unavailable mark `REVIEW_BLOCKED`; never simulate Goldfish reviewers in the parent context or claim an approval from a CI/doc test. The H199 TRAIN allowlist remains empty until separately proven rights and owner authorization. No private evaluation material may be included in a design review packet. All architectural implementation remains subject to existing founder authorization and Draft PR controls.
