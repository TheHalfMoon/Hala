## Actual original source design and rendered images

`h48/factory.py` authors 128 unique **first-party CC0-1.0** fictional GUI scenes, evenly split 64 English LTR and 64 Arabic RTL, **eight new app/task families** not reused from H43 or H44 public DEV or H47. Each scene has four visible labelled actions, a separately authored task instruction explicitly naming the intended action, and one supervised pixel-coordinate centre derived from **real browser DOM**, not guessed by the image author. All scenes are **train_only**. Eight distinct widget/layout topologies: sidebar, table, toolbar, settings, grid, modal/dialog, kanban and tabs. Representative labels come from original 24-word English/Arabic controlled vocabularies. No real user account, passwords, PHI, copied webpage assets, third-party benchmark tasks or external API/network service.

Actual Windows Edge Chromium `Edg/155.x` headless rendering using preinstalled/pinned `puppeteer-core 25.12.0` generated 960×540 real PNG captures for **128/128 source cases**. The runner blocks HTTP(S) requests and accepts only original `file:` pages. The trusted evaluator records exactly four DOM action names/boxes per page for supervised training labels (total **512 original control rectangles**). `h48/audit.py` independently reauthors each original HTML page, verifies screenshot bytes, dimensions, SHA256, language, all control names and geometry, absence of overlapping or off-screen targets, and center-to-rect arithmetic.

**Original H48 v1 quality rejection:** Initial deterministic offset schedule (`n*3` mod 24) yielded 128 PNG files but **only 64 unique image SHA256 hashes**; `tests/test_h48_diverse_visual_training.py` correctly failed. v1 is **not qualified as data**; no v1 PNGs are committed or used for training. Improved `n` offset was rendered to a *new create-only* `h48/assets-v2/` directory. This produced **128/128 distinct actual browser PNG hashes** and passed all 5 focused quality tests. Do not reframe v1 as 128 independent observations, and do not silently rewrite v2 artifacts.

**Critical:** These labels are deliberately suitable for supervised training. Train/DEV separation means never concatenate H44/H45/H46/H47 *public DEV* source or evaluator-only frames into `h48` training exports and then claim any future performance on H44 as out-of-sample. Diversity of rendered app names and layouts does not prove robust generalization to unseen real applications.
