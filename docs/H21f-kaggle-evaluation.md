# H21f evaluation provider operation

The default remains Colab. An operator may explicitly pass `--provider kaggle` to `python -m evaluation.development_runtime` only after actual eligible free Kaggle GPU, internet, package, font/RAQM and frozen-data checks. All existing external source/manifest/adapter identity flags still apply. The Kaggle evaluation guard accepts Linux plus explicit development opt-in, an Interactive/Batch Kaggle marker and /kaggle/working. Under [ADR0006](adr/0006-recognize-inherited-kaggle-image-marker.md), an inherited Colab image tag is permitted within that complete Kaggle context and recorded verbatim as inherited_colab_release_tag in evaluation_provider provenance. Colab evaluation still rejects Kaggle context. These markers do not attest billing eligibility, hardware or quality.

The original training remote_guard is unchanged and remains Colab-only. No generic Linux/provider fallback, environment spoof, package relaxation, retraining, parser repair or source-data change was added. Frozen SETTINGS and complete QwenInfer AST remain identical to the actual Colab baseline. Initial source qualification is recorded in docs/reviews/h21f-source-gates.json; the inherited-image repair requires its separate source gates. The actual Kaggle Interactive runtime now has a live T4, /kaggle/working and COLAB_RELEASE_TAG=release-colab-external-images_20260917-060051_RC00, with reported Python 3.13.15 and Torch 2.11/CUDA 12.8. This replaces the earlier disabled GPU/internet UI observation. Full package/font/model qualification and matched inference remain pending.
