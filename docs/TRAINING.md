# Remote training and baseline experiments

The portable source is in `training/scripts/`; platform notebooks are derived by `python -m training.platforms.build_notebooks`. Do not maintain separate Kaggle/Colab/Modal training implementations. Platform eligibility is independent of technical GPU availability.

The actual Kaggle probe measured two T4 devices with 15,636,037,632 bytes each, CUDA 12.8, torch 2.11.0+cu128 and successful FP16 tensor updates. That is not checkpoint training. BF16 is not native on T4, and memory is not pooled. Official Kaggle terms restrict use to internal, personal, noncommercial purposes, so Hala commercial-development model workloads are blocked there.

The Colab notebook first probes a real device, then installs an exact official Transformers version and offers eight original unchanged Qwen3-VL-2B GUI diagnostics. It downloads weights only into a remote temporary cache. A 20-minute alarm and 80-token/45-second generation limits bound the diagnostic. This is target geometry only, not native computer execution or general bilingual qualification. Use ordinary notebook or the officially supported client methods, never quota evasion or a customer-serving free notebook.

`python -m training.scripts.train_adapter --config ... --examples ... --manifest ... --baseline ... --output ...` implements candidate Qwen3-VL LoRA supervised adaptation. It requires an explicitly enabled remote Linux environment, pinned revision, rights-cleared train-only JSONL artifact digest, family-level holdout separation and a real measured baseline deficit. It rejects Kaggle while eligibility is blocked. The runner masks the entire prompt/vision prefix, checks completion token alignment, freezes base weights, uses FP32 LoRA optimizer values with FP16/BF16 autocast, gradient accumulation/checkpointing, finite-gradient checks, clipping, safetensors adapter exports, hashes and optimizer/scaler resume state. Batch size one only is implemented.

This runner has not executed a model training step yet. Preflight unit tests and a GPU tensor probe do not qualify its processor masking, actual adapter training, memory use or resume equivalence. No adapter exists. PEFT target-module selection includes all matching q_proj/v_proj modules and must be narrowed/frozen appropriately if vision adaptation is not desired before a real experiment. QLoRA and quantized training are NOT IMPLEMENTED. Modal is an unqualified deployment target and no job API is invoked. Standard Linux and Colab invoke the same runner after eligibility and runtime qualification.

After a real training run, independently evaluate the unchanged base and adapter on identical held-out families, retain exact environment/package versions and hashes, and reject unverified improvement. Store all large data/checkpoints remotely; retrieve only bounded results and manifests to Git. Never overwrite an existing experiment without an explicit resume, and never load untrusted optimizer artifacts as general pickle (`weights_only=True` is used).
