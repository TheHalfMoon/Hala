# H21b unchanged shared-base development runtime

This implements a remote evaluation entry point. CPU fake-seam tests do not
establish model quality, actual GPU performance, Arabic quality or successful
closed-loop tasks. Root must integrate reviewed H19 source, prospectively freeze
qualified bilingual media/settings and publish reviewed source before a real run.
No local ML dependency, model weights or paid service is needed for the tests.

The runtime accepts only Linux with an actual Colab release marker, explicit
`HALA_REMOTE_DEVELOPMENT_ALLOWED=1`, and no Kaggle runtime marker. These environment
checks prevent accidental local execution; they are not cryptographic hardware
attestation. All guards, external manifest/source verification, settings equality,
font hash, clean source commit and exact package metadata checks precede ML imports
and model allocation. Imported package versions are checked again. Pins are Torch
2.11.0, Transformers 5.16.1 and Pillow 11.3.0; media requires RAQM 0.10.1 and H19's
existing pinned font. The model is Qwen/Qwen3-VL-2B-Instruct revision
`89644892e4d85e24eaac8bacfd4f463576704203`, FP16, SDPA, greedy seed42 with
deterministic algorithms, no TF32 and no sampling.

## Prospective freeze and invocation

The exact settings to archive are the plain dictionary
`evaluation.development_runtime.SETTINGS`. It fixes the model/revision/precision,
attention, seed, deterministic flags, 4,096 expanded input tokens, 128 completion
tokens, 20-second generation stopping budget, 16 model calls and eight Type actions
per episode, and a 3,600-second experiment deadline. A settings file with any
change, missing field or extra field is rejected. Boolean/integer substitutions
are distinguished by canonical JSON comparison. H19 separately freezes the
actual authoring, prompts, parser, simulator, verifier and renderer source hashes.

After reviewing H19 and this runtime, freeze media using
`development.freeze.freeze_bundle(output, SETTINGS, font_path)` on the qualified
remote renderer. Archive its manifest SHA256 independently before inference.
Do not read an expected manifest digest from untrusted downloaded bytes.

From an isolated Colab worker subprocess on the published clean commit:

```text
python -m evaluation.development_runtime --bundle FROZEN_BUNDLE --manifest-sha256 EXTERNAL_SHA256 --font-path PINNED_FONT --source-commit EXACT_COMMIT --split dev --output NEW_RUN_DIRECTORY --cache-dir /tmp/hala-h17-cache
```

The cache option supports reuse of an existing approved remote cache. Resolved
paths must be below `/content` or have `/tmp/hala-` as their prefix. Model and
processor loads use the exact revision and `trust_remote_code=False`. No
credentials are accepted or transported by the entry point. The reserved
`--adapter` option always fails before loading; archive verification and adapter
inference require a later reviewed integration.

Choose `dev` or `test` for closed-loop episode families. The independent standalone
Mind cases retain their authored `test` allocation even during a `dev` episode run;
the result records each case's allocation. The runtime does not tune prompts,
repair JSON, retry failed outputs or substitute oracle answers. All response
interpretation and transitions use reviewed H19 source.

## Inputs, outputs and measurement limits

The model callback receives only component name, public prompt and current frame
path. Mind and Reliance text callbacks accept no image. Type requires a bounded
800x600 PNG inside the run's current-frame directory; the actual PNG hash is logged
before preprocessing. It receives neither episode objects, expected coordinates,
private labels nor desired final states. Off-path state frames are generated by
the reviewed renderer and retain its per-frame provenance through the H19 runner.
Structured observations describe current public state, as specified by H19.

Each model call retains the raw decoded string, image hash, prompt, token count,
preprocessing/generation/wall seconds and before/after memory samples. Bare JSON
validation is H19's responsibility; even fenced/prose/malformed outputs are retained
without repair. Episode records preserve proposals, actual synthetic transitions,
final state, independent completion check, action/schema/semantic errors, unsafe
and unnecessary suggestions, recovery and call counts. No native action occurs.

The per-language summary separates standalone Mind exact-label correctness,
episode Mind semantic correctness, planning counts and complete-task outcomes.
It refuses to summarize episodes without the reviewed `mind_correct` semantic
metric, preventing the older runner from presenting task success as planning
accuracy. Whole-task completion never implies every Mind proposal was correct.

Telemetry includes load/wall/model generation/process CPU seconds, GPU identity,
CUDA capability/version, allocated/reserved CUDA peaks, full-device used samples
and current/peak Linux CPU RSS. Full-device memory includes driver/other-process
usage and is sampled rather than continuously profiled. CPU RSS is process
resident memory, not the entire machine. No throughput, concurrency or total
production serving cost is inferred from this sequential run.
Telemetry is best effort: an unavailable sample is `null` with an explicit
`telemetry_errors` entry. Sampling or CUDA cache cleanup failures cannot erase a
completed raw call, mask its original inference failure or prevent blocked-result
publication. The maximum device-memory sample uses only available measurements;
it is `null` when none exist, rather than an invented zero.

Transformers `max_time` stops between generation iterations and cannot preempt a
hung GPU kernel. A Python alarm plus persistent monotonic checks prevent a caught
deadline exception from permitting further model calls. Run in a separate worker
with an external process timeout as the final containment boundary; this runtime
does not claim CUDA preemption. No server or production endpoint is started.

Every run requires a new output directory. Canonical JSON is fully encoded before
opening a temporary result, flushed/fsynced and atomically replaced. Partial
blocked results and completed calls survive caught failures; they receive no
full-run score. This does not guarantee survival of VM loss or forced process
termination between checkpoints. Remote artifact persistence remains the root
workflow's separate prerequisite before training.

## Validation

Initial tests failed because the runtime module did not exist. Four initial tests,
then seven fake-seam tests passed. The integrated suite passed 160 tests in
25.128 seconds. After adding monotonic deadline containment, all eight final phase
tests passed in 0.322 seconds. Tests exercise guard rejection before loading,
immutable settings/hash checks, atomic failure preservation, separate task/Mind
metrics, public text/image boundaries, untouched raw output, token limits, CUDA
failure records and refusal to start further calls after deadline expiry. No GPU
execution occurred during this builder phase. Independent review and genuine
Jev/Graft qualification remain pending.

Cycle1 independent combined review reproduced loss of a completed call when its
post-call memory sampler raised. Two new regressions failed before repair. The
repair isolates sampling failures before/after calls and during finalization,
keeps the original inference exception, and atomically persists the blocked
result even if final sampling/cache cleanup fails. All ten phase tests passed
after this repair; no model execution or full-suite rerun was needed for the
focused delta. Fresh independent delta review and updated tool evidence remain
the conductor's next gate.
