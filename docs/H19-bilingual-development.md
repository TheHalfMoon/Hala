# H19 bilingual development inputs

This new experimental protocol is independent of frozen H14/H17 and the H18 historical audit. It provides original CC0 text and synthetic interfaces, not native computer execution or measured model quality. No models or weights are downloaded by this package. Mind plans decompose replacement, movement, saving and independent verification into bounded tool/subgoal objects; no unrestricted executable text is accepted.

`build_dataset()` authors 32 episodes: four training application families (recipe box, music queue, garden log, craft board), two development families (reading shelf, pet journal), and two test families (museum catalog, sports roster). Each family has English and Arabic, each with a normal and transient-save-failure variant. None is an H14 family. The 136 training turns share a base checkpoint with component-specific prompts: Mind planning/tool selection/recovery/clarification/abstention, Type normalized click/type/drag, and advisory Reliance. Ten separately worded test Mind decisions cover all five Mind categories in both languages. Train/dev/test application families are disjoint; UI layout and workflow templates are shared and dependent. Counts are not independent sample sizes.

Each workflow replaces a visible text field, drags a card into a named destination, and saves. All sixteen family/variant layouts differ; Arabic mirrors every box. Shared workflow templates remain a limitation. A failure variant rejects the first save and requires observation before retrying. Environment failures are counted separately from model action errors, and redundant Mind observations count as unnecessary calls. Final success checks actual current and persisted values, card destination and a real save revision in `development/verifier.py`, which imports no simulator, oracle, or parser. The simulator is the sole state mutator in evaluation. Malformed output, wrong targets, bad order, redundant actions, recovery and calls are recorded. Native execution, authorization, arbitrary commands and model success receipts are absent. Strict bare JSON rejects duplicate/extra fields, booleans, nonfinite and out-of-range coordinates and unknown tools. Proposed type text is limited to 80 printable characters.

`development.runner.run_episode(episode, infer, media_dir, font_path, max_calls=16)` calls `infer(component, prompt, image_path) -> str`. Mind receives no image; Type receives the newly rendered current screenshot. The callback receives only public user goal and visible state, never expected boxes, private final state or oracle labels. Mind chooses the tool, and Type chooses the next action under the full goal; no oracle-known next action is placed in its prompt. The first response must be a plan, later responses must be next steps; wrong kinds consume a call without invoking Type. A separate semantic checker derives the required decomposition/subgoal from the public quoted goal values and visible state, without importing the oracle or simulator. It records per-call requested-kind and semantic correctness plus `mind_errors`, `mind_accuracy` and `plan_accuracy`. Wrong semantic subgoals do not rewrite the model's selected tool or leak a corrected subgoal to Type. Therefore task final success and Mind semantic quality are separate measurements: Type can finish despite bad Mind decomposition. `run_mind_cases(cases, infer)` scores the separate text decisions. A failed Mind parse consumes a bounded call; clarification/abstention stops that episode without success. The synchronous callback must provide its own model timeout; the loop limits calls, not arbitrary blocking callback execution. It records individual latency and wall/model seconds; a remote wrapper must add actual CUDA/device telemetry.

Training rows include private audit state separate from `prompt` and `completion`; adapters must feed only those latter fields and an image. `training-rows.jsonl` in a qualified bundle materializes `image` and `image_sha256`; rows retain language, component, split, family and episode provenance. This is a new semantic export, not an input accepted by the historical action-only loader. A later reviewed bridge must validate and load it without editing the old audit. Mind images can be used for training compatibility, although actual Mind baseline is text-only; that modality difference must be resolved explicitly in the training bridge.

Run `tools/build_development_data.py --output NEW_DIRECTORY --settings FILE [--font FONT]` to freeze deterministic inputs and source hashes without overwriting an existing directory. Omitting the font produces a text-only authoring freeze with no media qualification or materialized training rows. A remote media freeze requires Linux, Pillow 11.3.0, RAQM 0.10.1 and DejaVuSans.ttf SHA256 `ae7b7855e115a5966d8b1b3f80f254ccc117ec86f9965e202ee2940453837280`. Arabic drawing explicitly sets RTL, Arabic language, RAQM and right anchors. It freezes initial/oracle-path images, dimensions and exact media/font/runtime hashes before baseline outputs. Off-path states during real evaluation are rendered with the same frozen source and logged separately, because model mistakes cannot be predicted in advance. Verify the bundle and independently archive its manifest SHA256 before inference; hashes within an attacker-rewritten manifest alone are not an external trust anchor.

Qualified `verify_bundle` requires a caller-supplied externally archived manifest SHA256, checks loaded source against frozen code, enforces actual media/row/count consistency, rederives semantic rows, and checks font/runtime/dimensions and image bytes. Its source-only mode cannot claim media qualification. The local tests qualify text, parser, simulator, final verifier, freeze behavior and a mock-rendered callback loop only. They do not qualify Arabic image shaping. No actual data media, baseline inference, GPU performance, LoRA quality, durable adapter or serving improvement has been measured in H19 source work. The proposed settings file is explicitly unexecuted. Required independent review and Jev/Graft qualification follow source tests before commit.
