## Proposed competitive edge — a systems/data program rather than prompt tweaking

1. **Model bake-off (R0):** Retain the exact unqualified Qwen3-VL-2B source/evidence as control. Compare additional *rights-cleared* candidates on identical DEV images, then preregister a held-out study: Apache Holo4-35B-A3B as long-term candidate, OpenCUA 7B/32B and available UI-TARS open-weight candidates only after individual model/data license, GPU memory, attention implementation, loader and privacy preflights. **Do not assume** 35B-A3B trains or fits on a free T4; two T4 cards are NOT pooled VRAM. No paid API fallback and no new H23 experiment duplication.
2. **Agentic task factory (R1):** Build auditable first-party, rights-cleared **new UI environments** with independently verified state-delta oracles for web, desktop and tool/MCP workflows. Start with 100-200 authoring/DEV workflows and reserve a **separately created, family/app-disjoint blind evaluation** with Arabic and English. Each verifier must fail on untouched initial state, pass a golden target, reject realistic near misses and unauthorized mutations. Do NOT label first-party manufactured tasks real app benchmarks or independent blind TEST.
3. **Diverse supervised trajectories (R2):** Capture permissioned observation→plan→action→verification trajectories with explicit tool budgets, click label/point, wrong-target, abstain, layout scaling, step budget, error and correction, protected affordance, RTL font/text ambiguity, task intent and success oracle. De-identify before storage; no PHI, credentials, or copied proprietary page assets. Govern per-trajectory license and dataset composition. Use failures deliberately, but don't inject evaluation tasks into training.
4. **Separate HalaMind / HalaType / HalaReliance (R3):** HalaMind handles task decomposition + next-action choice; HalaType performs pixel/element localization with coordinate-space calibration, text/icon disambiguation and RTL; Reliance-type gate estimates calibrated risk and selects action/abstain/escalation. Use shared model or experts only when real paired ablations show better correct **task completion** and lower unsafe/error rates. H38/H39 safety policy remains host-owned, not a substitute for model learning. Model code, weights and training license and host integration reviews remain separate.
5. **Mixed interface policy (R4):** GUI-first for apps without APIs; use explicit trusted MCP/API/CLI only under user permissions, same task policy, and independently checked postconditions. Benchmark GUI-only separately from GUI+tools to avoid artificially inflating results. Never bypass protected screens, CAPTCHAs, access controls, or session consent.
6. **Optimize cost/latency (R5):** Choose quantization/speculation/caching/distillation only after score preservation, measure per-task successful cost, p50/p95 end-to-end, GPU peak memory, crash/recovery and degradation by language. A smaller lower-cost specialized model can be the best *Pareto option* without claiming #1 raw accuracy.

## Public benchmark program — prospective gates

- **S0, source + contamination lock:** Record model checkpoint SHA, tokenizer/processor/revision, license of model and dataset, eval source SHA, benchmark release, task/asset SHA, official scoring script, virtual machine/container image, screenshots, tool surface (GUI-only vs GUI/code/MCP), budgets, number of actions, timeouts and retries. Explicitly freeze training families and exclude all official private/held-out tasks. Never publish benchmark privileged answers with training data.
- **S1, grounding:** ScreenSpot-Pro (professional), ScreenSpot-V2 (desktop/mobile/web diagnostic), OSWorld-G as available. Report each language/platform, raw click-target correctness, abstentions, unique **wrong** control selections and hallucinated off-target points. One-step localization alone is not task quality.
- **S2, real multi-step:** OSWorld 2.1 official success and partial scores **separately**, on unmodified environments with per-task hidden state verifier. Compare each candidate and baseline under identical **official version, harness, tool surface, hardware, budget and stopping rule**. Public OSWorld 1.x is a distinct historical line; never claim Hala beat OSWorld 2.1 using OSWorld 1.x percentages.
- **S3, bilingual independent challenge:** Independent linguists review original Arabic phrasing and app labels; stratify at least 50 Arabic and 50 English tasks for a preliminary comparison, plus icon-only, high-DPI, window changes, text in pictures, ambiguous labels, changed frames, long workflows, wrong-target refusal, and safe user-approved recovery. Keep task families, interface templates and application identities disjoint across training and blind tests. If sufficient independent Arabic test content or raters aren't available, report **NOT_YET_QUALIFIED**.
- **S4, replicated paired cost/quality:** At least three independent end-to-end runs/seeds where feasible; log every task and failed/timeout attempt (no success-only denominator), same budgets and task order randomization. Report overall and per-language success with Wilson 95% CIs; paired discordant wins/losses, exact McNemar *descriptive* p and task-dependence caveats; p50/p95 task latency, hardware, $/task, peak memory and **unsafe event count**. No production launch based on descriptive p values.
- **S5, public claim:** Only after independent evaluator or official leaderboard accepts actual frozen version/cases, no training/test contamination, substantive code security review, authentic postconditions, trusted host approval, reproducible raw receipts and signed provenance. "Beats model X on benchmark Y/version Z under W" is possible; **"best globally"** without exhaustive up-to-date comparable benchmarks is not. Every claim must include both denominator and scorer origin. Cost-only wins are separate from raw success leadership.

## H42 executable non-result gate

`evaluation/h42_paired_audit.py` reads **only receipts** (`hala.h42.paired-task-receipt.v1`), explicitly validates full known fields, hashes, bounded task identifiers, duplicate/missing cases, family-level train/test disjointness claimed by metadata, same GUI vs GUI+tool surface, finite latency/cost, unsafe flags and Arabic/English strata. Computes paired wins/losses, descriptive success, Wilson 95% CIs, exact McNemar p, cost and latency. Rejects nonfinite/duplicate-key JSON and never overwrites a prior audit file. **Even if client-supplied `independent_oracle_claim=true`, the generated report keeps `independent_oracle_verified=false` and `claim_top_rank_qualified=false`**; a local JSON cannot authenticate independent evaluation. Unit tests use fabricated synthetic rows **only to exercise validation**, not report any model results.

Example invocation once genuinely independent externally authenticated task receipts exist:

```powershell
python -m evaluation.h42_paired_audit --input PATH_TO_REAL_PAIRED_RECEIPTS.json --output NEW_UNIQUE_AUDIT.json
```

No H42 model/GPU inference run has occurred, and this source-only protocol does not use paid APIs, alter H23/H37 immutable data, change existing execution routes, or grant local OS control.
