# 0002. Default to deterministic routing pending measured ablations

Status: accepted (2026-10-14)

## Context
An existing local d1-omni-600M Q8 GGUF runtime supports typed advice. Three authored English route diagnostics returned expected labels with 536–781 ms tool latency, while three longer Arabic routes returned HTTP 400. The six-case diagnostic is not a heldout routing benchmark. The large-model comparison and net compute savings are unavailable.

## Decision
Keep the Hala fixture router deterministic and treat d1 solely as research/advisory triage. Do not add a resident Reliance model, adopt Liquid commercial rights, lower local policy or require its inference on every step. Measure actual complete-task quality and saved expensive calls before changing the default.

## Consequences
Current mock inference needs no proprietary API and cannot gain authority from a model score. Learned routing quality, Arabic transport, exact native runtime compatibility, licensing and serving cost remain qualification work. CPU tool timings include MCP overhead and do not establish vendor model latency.
