# H398 — private original synthetic bilingual GPU research pilot

This **does NOT train Hala 35B, Qwen3-VL-2B, or an officially H199-admitted GUI adapter.** It is a tiny independently initialised CNN plus six learned instruction-ID embeddings (~35,840 parameters), a controlled GPU training infrastructure sanity check only. Nothing here authorises use of previously collected screenshot corpora, rightsholder assets or sealed OOD tasks.

## Data origin and isolation

All images are generated by `h398/kaggle/h398_synthetic_gpu.py` from simple color-grid rectangles in PyTorch memory. No photos, copied UI sources, downloads, model weights, private user files, Kaggle datasets, additional notebooks or internet requests are loaded. Three deterministic original synthetic sets are created with separate seeds: 960 TRAIN, 180 DEV, 180 *author-exposed* alternate-style research tests. Six synthetic instruction identifiers stand for combinations of **English/Arabic × red/green/blue target**; this is **not free-text bilingual comprehension**. No real UI, third-party fonts/icons, sealed source families or genuine previously unseen evaluation custodian.

The experiment checks no duplicate image+instruction identities between splits, trains on GPU T4, and records before/after accuracy separately for two synthetic language-label groups. These are toy model outcomes, *not* Hala inference, blind OOD generalisation, release safety or legal clearance.

## Private bounded Kaggle execution

Metadata: `h398/kaggle/kernel-metadata.json` uses `is_private: true`, `enable_internet: false`, `dataset_sources: []`, `kernel_sources: []`, `model_sources: []` and T4. Run through owner-authenticated Kaggle CLI:

```powershell
kaggle kernels push -p h398/kaggle --accelerator NvidiaTeslaT4 --timeout 1800
kaggle kernels status abdulazizshehri/hala-h398-original-synthetic-bilingual-gpu
kaggle kernels files abdulazizshehri/hala-h398-original-synthetic-bilingual-gpu
```

Private kernel: https://www.kaggle.com/code/abdulazizshehri/hala-h398-original-synthetic-bilingual-gpu

The run must produce a JSON receipt and tiny research weights only at `/kaggle/working/h398-synthetic-research/`, never commit weights or expose a dataset externally. On failure, report the actual error and do not count it as completed training. The model is intentionally not a deployable version of Hala.

## Owner Kaggle result — source-only synthetic experiment

- Owner Kaggle private kernel version 1 **COMPLETE**, Tesla T4 selected and two CUDA devices visible; no external datasets or Internet permission in returned private kernel metadata.
- 960 algorithmic TRAIN examples; 180 DEV and 180 different-style research examples. Original randomly initialized model **35,840 parameters**; 160 real GPU optimizer steps, recorded training loop time 1.15 seconds. These are not Hala or Qwen weights.
- DEV initial overall 31.11% (EN 33.33%, AR 28.89%) → trained overall **100%** (EN 100%, AR 100%).
- Alternate-style author-exposed research split initial overall 27.22% (EN 28.89%, AR 25.56%) → trained overall **100%** (EN 100%, AR 100%).
- This is a **trivial algorithmically generated color-grid recognition task** with six fixed instruction IDs; its accuracy is NOT evidence of generalizable real-world GUI grounding, text comprehension, pretrained model improvements, independent OOD or readiness for release.
- Exact Kaggle receipt JSON and SHA256 were retrieved and verified locally; `python -B h398/validate_receipt.py` validates the immutable evidence without GPU. The original tiny weight file remains **only in the owner's PRIVATE Kaggle kernel output**, not in the Git repository.
- Kernel source pull returned Kaggle's Python script with a bytewise SHA differing from our original .py; no claim of byte-for-byte on-platform source attestation is made without resolving the source transformation.
