## What H267 changes

One private, authorized **FREE noncommercial Kaggle NvidiaTeslaT4** script
loads the pinned Qwen/Qwen3-VL-2B-Instruct revision
`89644892e4d85e24eaac8bacfd4f463576704203` and the existing
H208 visual policy. It tests **two preregistered prompt variants**, each
on a new clean offline first-party H262 Stockroom context:

1. `original_h199`: unchanged screenshot-only H199 action prompt.
2. `strict_json_reminder`: the same prompt plus explicit exact JSON
   formatting reminder with `click`/safe `abstain`. No hidden DOM,
   gold, target pixel or oracle geometry provided to model.

This is deliberately **one first-party research task repeated twice**,
not a fresh, independent held-out benchmark. Greedy decoding with at
most 160 new tokens for each arm. No sampling sweeps or post-hoc
selection of success. A H208 wrapper classifies the model's actual
continuation **in volatile memory** into exactly one of: strict
valid native JSON; JSON wrong schema; markdown fence; non-JSON;
empty text; or no decode. It stores only category, never text or
coordinates. It never modifies decoded text or relaxes H199 parser.
INVALID output triggers NO browser action, and no fallback oracle click.

H264 screenshot-stale validation and H263 native actuator execute
the strict action if valid; a separate evaluator then compares the
first item's original stock quantity, without passing that quantity
to Qwen. The public program has **zero weights/images/gold**.
