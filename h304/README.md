# H304 — source-owned pre-dispatch write authorization

## Proven unwanted-write defect

The H303 FieldPort evaluator already stopped a **wrong first-field click**
before a second neural generation. However, a *syntactically valid* but
incorrect `type_text` value still reached the real browser actuator,
which wrote the wrong fictional code into the correctly focused input
before the final all-four-field source oracle scored failure. A changed
active input between the second screenshot and dispatch was another
possible unsafe write. Post-hoc task failure does not undo either write.

## Narrow fail-closed repair

After the second source-locked model prediction, **before** calling the
unchanged H263 native actuator, the independent original FieldPort
source-owned evaluator checks:

1. A predicted `type_text` code exactly matches the already requested
   fictional user-visible code, with no replacement, fallback or retry.
2. The *currently* active native input is still the requested source field.
3. All four original form values remain empty on refusal.

If either authorization condition fails, **no type is dispatched**.
The already-produced second neural generation remains counted and the
task remains a failure. The evaluator returns only a categorical
`source_write_guard_refused` boolean; no source field ID, correct
code, DOM, coordinates or gold enters the model prompt, grammar or
prediction. The policy receives no retry feedback. H298's terminal
failure latch seals the two-stage policy after this source refusal.

The receipt deliberately distinguishes a **model-generated** valid type
action from a **native browser-dispatched** type action. It is incorrect
to subtract the refused generation or count it as a successful action.
A correct type, an abstention, and a wrong first-field click preserve
their existing behavior. This source-specific gate is an actuator
safety measure, not a claim that Qwen learned to choose the right code.
